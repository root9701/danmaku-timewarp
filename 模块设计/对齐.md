# 对齐模块 模块设计

> 创建 2026-10-27 | 版本 v1 | 归属：架构总览 §模块 表 `server.py` 的自动校准部分

## 一句话职责

给定「某晚直播的音频指纹」和「某个官方回放分P 的音频指纹」，求出该分P 的 t=0 对应直播墙钟的哪一刻。

## 接口

| 接口 | 输入 | 输出 |
|---|---|---|
| `audiofp.align(ref, query, hop, valid_range=None)` | 直播指纹矩阵、回放片段矩阵、帧长、可选搜索范围 | `{offset_sec, confidence, best_score}` |
| `_align_one_page(fp_replay, conns, hop, min_conf, min_match_sec, anchor_ms=None, window_ms=None)` | 回放指纹、全部连接段、阈值 | `{offset_ms, offset_sec, confidence, votes, candidates, picked_by, suspect, ...}` |
| `run_autocalign(date, file, bv, page, session)` | 会话坐标 + BV + 分P（0 = 全部） | `{pages:{...}, errors:{...}, elapsed_sec}` |

## 边界

- 允许依赖：`audiofp`、`server` 内的目录/元数据读取、B站取流（`bili_view`/`get_replay_fingerprint`）
- 禁止依赖：`web/` 的任何内容；`danmaku-collector/` 的任何模块

## 该测什么

1. 从参考里截一段当查询，`align` 必须还原出原始偏移（±0.05 秒）
2. 两处完全相同的片段、只允许其中一处时，必须返回被允许的那处（时间窗约束）
3. 完全无关的随机音频，`_align_one_page` 必须抛 `ApiError` 而不是采纳
4. 簇内离散 > 容差的散票不得凑成「一致」（防链式聚类假一致）
5. 最强票 conf < `min_confidence` 的簇不得算证据（随机水平约 1.1~1.35）
6. 命中音频总时长 < `min_match_sec` 时必须拒绝（随机噪声在长片段上 conf 可到 2.5~5.5）
7. 采集端与播放端的指纹函数必须逐 bit 等价

## 验收标准（人话）

- 2026-10-26 那晚四场共 10 页仍能全部对齐，且 offset 与既有记录一致（不因改算法漂移）
- 2026-10-27 仍为 8/9 页，缺的那页报「无音频」类明确原因，而不是静默错位
- 早间重播的伪峰被拒，提示里能看出「距赛程窗口偏了多少分钟」

## 已知约束

- 指纹要能跑在手机 Termux 上，因此采集端保留独立副本，不做模块共享；一致性靠测试卡
- `align` 内部限制搜索范围（`valid_range`）是硬要求：先取全局峰再过滤，窗口内的正确峰根本不会出现——这个坑踩过一次，见 `SCHEMA.md` §4.4
- 对齐是 CPU 密集同步计算，必须走 `asyncio.to_thread`，否则会堵住事件循环
