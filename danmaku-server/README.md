# danmaku-server 伪直播播放端

把采集端录下的弹幕对齐到 B 站官方回放视频上，在本机把录播还原成一场"正在直播"的页面。

总览见上级目录 `README.md`，数据契约见 `../SCHEMA.md`。

## 启动

| 脚本 | 作用 |
|---|---|
| `Start.bat` | 前台运行，仅本机可访问。**关窗 = 停止服务** |
| `Start-LAN.bat` | 前台运行，手机或平板可访问，窗口里打印二维码 |
| `Stop.bat` | 停止服务（按端口 8789 精确定位进程） |

换机器需重建 `.venv`（aiohttp + numpy + imageio-ffmpeg）。

## 页面操作

1. 选**日期** → 选**比赛场次** → 点「开始播放」。
2. 点**「自动校准」**：服务端用直播音频指纹与回放音频比对，解出 offset 并自动应用。首次约半分钟（要下载并计算回放音频指纹，之后有缓存）。
3. 看比赛。弹幕密度/字号/数量按需调整，控制条有弹幕快捷开关和全屏。

辅助功能：

- **刷新赛程**：Riot 官方赛程发现当日场次 + B 站搜索官方回放 BV 回填。回放未上传时留空，中午后再点一次即可补齐；当天新增的场次会直接补进场次列表。
- **手动微调**（自动校准不准时的兜底，默认折叠）：±30/10/5 秒逐档校正，即时生效并持久化。
- **自定义回放源**：无场次数据时手填 BV + offset。

「当晚总览」显示整晚的弹幕密度曲线和每场每分P 的时间位置，点色块可跳到该场该局。

## offset 语义

`offset_sec` = 弹幕墙钟锚点（`anchor_ms`，该会话首条弹幕时间）与回放 0 秒的差：

```
直播墙钟 = anchor + offset + 视频内位置
```

**每个分P 有独立的 offset**。播放器把各分P 首尾相接拼成一条虚拟时间轴，而直播侧两局之间有
局间休息（官方回放剪掉了），所以映射是分段的：

```
分P k 占虚拟轴 [S_k, S_k+Dur_k)
虚拟位置 v 的墙钟 = anchor + offset_k*1000 + (v - S_k)*1000
```

用单个标量 offset 等价于假设"各分P 无缝相连且与直播等长"，从第二局起就会错位——
实测 AL vs TLAW 第二局偏 −213.9 秒、第三局 −207.8 秒，TSW vs LOS 第二局 −224.9 秒。
局间休息里的弹幕直接丢弃，不压缩到相邻分P。

自动校准、手动微调、写回共用同一语义。

## 自动校准算法

把回放的音频指纹切成 8 段（每段约 3 分钟），分别去整晚直播指纹里定位，按 30 秒容差聚类投票。

**为什么切段而不是整段**：整段对齐时，只要混进一段直播没播的内容，整窗得分就被拉平，反而判不出来。实测同一局比赛，全长对齐 conf=1.01，切段后 conf 高到 5~9。

**判定看投票一致性，不看单段置信度**。单段 conf 反映的是"这 3 分钟音频本身有多独特"，
BP/解说段天然不独特（低到 1.1），但不代表位置错。实测 T1 vs CFO 第一局 8 段全部指向同一处
（离散 0.0 秒），只有 1 段 conf=8.28。若先按 conf 过滤就只剩 1 票，正常比赛会被判失败。

采信条件（其一即可）：票数 ≥ 1/3、强票（conf≥6）≥ 2 张、1 张强票（conf≥7）且总票数 ≥ 2、
或全票一致且最强票 ≥ `min_confidence`。

**赛程时间窗约束**：直播间常把前几场在早上重播一遍，音频与官方回放完全一致，投票也会一致命中。
因此按 `lists[].start_ms`（官方赛程开始时间）算允许区间，窗口外的一律拒绝：

```
窗口 = [start_ms - 90分钟, start_ms + 该场全部时长 + 30分钟]
```

搜索限制在 `audiofp.align(valid_range=)` 内部完成——不能先取全局最大峰再过滤，因为重播那段
码率更高、峰可能更高，窗口内的正确峰根本不会出现在结果里。

多个自洽位置时**取最早的那个**（那是当时正在直播的那次）。

某个分P 全部候选都在窗口外时报"疑似重播，未采纳"；部分分P 失败不影响其它分P。

## 数据目录

采集端按 `data/{赛事日}/{房间号}/` 组织，服务端优先读 `manifest.json`，读不到才退化为目录扫描（兼容老数据）。

`/api/days` 返回的每个条目带 `start_ms`/`end_ms`（**扫描弹幕数据本身**取到的首尾时间，不是读 meta——采集端的 meta 只覆盖最后一次收尾的片段，用它当会话时间会严重错位）。

## 服务端 API（8789）

| 端点 | 说明 |
|---|---|
| `GET /api/days` | 日期列表（带 `match_date` 赛事日 / `data_date` 数据日） |
| `GET /api/danmaku?date&file` | 弹幕全文（多文件合并按 ts 排序，支持边采边读） |
| `GET/POST /api/match` | 对齐注册表读写（原子替换 + lists 同步）；带 `bv` 时返回该场逐分P 结果 |
| `GET /api/matchlist?date` | 该日场次列表 |
| `GET /api/discover?date` | Riot 赛程发现 + B 站 BV 搜索回填（内存缓存/退避/只回填空位，落盘 `start_ms`） |
| `POST /api/autocalign` | 音频指纹自动对齐（逐分P 多段投票 + 赛程窗口，`page=0` 全部分P） |
| `GET /api/overview?date` | 当晚总览（密度直方图 + 各场各分P 时间位置） |
| `GET /api/playurl?bv&page` | B 站 mp4 直链解析 |
| `GET /api/stream?url` | CDN 反代（带 Referer/UA，Range 透传，SSRF 防护） |

## 文件

- `audiofp.py`：指纹算法（0.4s 窗 33 对数频带能量 + L2 归一化）与 afp 解析、FFT 互相关对齐。
- `matches.json`：`align`（`赛事日|文件[|BV]` → bv/offset/pages）+ `lists`（`赛事日` → 场次数组）。原子写入。
- `web/`：无框架原生 JS。canvas 弹幕引擎 + 当晚总览 + 场次点选。

## 已知边界

| 情况 | 表现 |
|---|---|
| 取流走 B 站 html5，通常最高 720P | 直链偶发 403 自动走反代兜底 |
| 官方回放重导音轨 | 自动校准必失败（自动拒绝并提示），用手动微调兜底 |
| 直播只播了部分内容 | 该分P 只有部分能对齐，剩余内容播不了 |
| 某分P 内容在直播开播前（如赛前评论） | 报"找不到自洽位置"，下拉框显示「已对齐 1/2」，悬停看原因 |
| 早上重播了前几场 | 按赛程窗口拒绝，报"疑似重播，未采纳" |
| 官方之后又追加分P | 重新点「自动校准」即可补对齐；未补前下拉框会显示 N/M 不一致 |
| 采集时关了音频指纹 | 该晚无法自动对齐 |

## 局域网访问

双击 `Start-LAN.bat`（绑 `0.0.0.0`，窗口里显示二维码）。
只需要本机看就用 `Start.bat`（绑 `127.0.0.1`，不显示二维码）。

两个脚本都会**显式设置** `DANMAKU_HOST`，所以不受 `config.json` 里 `host` 的影响——
曾出现过「`Start.bat` 标题写仅本机、实际却绑 0.0.0.0 还打印二维码」，
就是因为配置文件里的 `0.0.0.0` 覆盖了脚本意图。启动时打印的「监听地址」一行会显示实际生效值与来源。

停止服务：关窗口，或双击 `Stop.bat`（按端口 8789 精确找进程结束，不误伤其它 python）。

`Start-LAN.bat` 会把监听地址设为 `0.0.0.0`，窗口里打印二维码。

手机连不上时，用管理员 PowerShell 检查防火墙：

```powershell
# 放行端口
New-NetFirewallRule -DisplayName "弹幕时光机" -Direction Inbound -Protocol TCP -LocalPort 8789 -Action Allow -Profile Private

# 检查是否有拦 python.exe 的规则(有则删除, 否则任何 Python 服务都不通)
Get-NetFirewallRule -Direction Inbound -Action Block | Where-Object { $_.DisplayName -eq "python.exe" }
```

本服务**没有登录鉴权**，只在可信的家庭/宿舍网络里用。
