# LOL 延时直播弹幕采集器

把电脑挂在指定的 B 站直播间，整夜自动录制弹幕（含 SC）和**直播音频指纹**（供次日自动对齐），早上拿到按整点切片的压缩记录 + 统计摘要。

总览见上级目录 `README.md`，数据契约见 `../SCHEMA.md`。

## 启动

| 脚本 | 作用 |
|---|---|
| `启动控制台.bat` | **推荐**：网页控制台(8787)，按日期排队、看赛程/日志、延长或提前结束 |
| `启动采集.bat` | 单次前台挂机：按 `config.json` 的时间等开播，适合只录一晚 |
| `退出控制台.bat` | 停止控制台(连带采集任务)，按端口 8787 精确找进程，不误伤别的 python |

日常：睡前打开控制台，把接下来几晚的任务排进任务表，点「启动队列」，窗口最小化即可。
控制台关窗 = 采集停止。

命令行等价用法（单次挂机）：

```bat
.venv\Scripts\python.exe collector.py --config config.json
```

## 任务队列

控制台里的「采集任务」按**日期**排队，一次可以排多晚，不用每天改配置：

| 字段 | 说明 |
|---|---|
| 日期 / 开始 / 截止 | 本地时刻。截止早于开始时按**跨零点**处理（次日截止） |
| 房间号 | 该任务要采的直播间；可多个 |
| 写入 | 数据目录日期 = **结束时刻**所在日（如 10-31 23:00→11-01 03:00 写入 `data/2026-11-01/`） |
| 状态 | 待执行 / 采集中 / 已完成 / 已结束 / 已错过 |

规则：

- **错过开始但没到截止** → 立即开录并记日志；**已过截止** → 标「已错过」，不补录。
- 同一房间的两个任务窗口重叠时拒绝保存（避免两个采集器写同一份数据）。
- 「结束本次」只收尾当前任务，队列继续等下一晚；「停止队列」收尾并退出。
- 「延长 30 分钟 / 1 小时」在到点收尾**之前**有效；已收尾后再延长只能开新会话，按钮会置灰。
- 「按赛程生成草稿」把当天赛程转成任务草稿（开始提前 30 分钟、截止预留 3.5/5.5 小时 + 1 小时），
  确认后点「保存任务」才落盘；不覆盖已有任务。
- 任务表存 `run/tasks.json`（整目录不入库），属于本机运行状态。
- 启动队列后，等待下一场期间也会阻止系统睡眠（Windows）；采集单实例锁与命令行 `collector.py` 共用，
  双开会被拒绝，避免两个进程写坏同一份数据。

控制台关窗或点「退出控制台」都会触发收尾（gzip + meta/manifest）。

## 夜间发布（随队列自动启动）

点「启动队列」时会同时拉起 `tools/nightly.py --loop`：每小时巡检一次，有回放就把
对齐结果写进 `data/{日期}/align.json`、重生成清单并做**本地提交**。

- 日志在 `logs/nightly.log`；发布失败只记日志，**不影响采集进程与已落盘数据**。
- 只 commit，不 push；推送仍需人工授权。
- 停止队列或关窗时一起停止；采集单实例锁仍只由队列持有。

## 产物（data/ 目录）

**一个会话一个目录**，赛事日 = 会话结束时刻所在日期：

> 默认写到**本脚本目录**的 `data/`（采集端可独立运行）。
> 本机配置里 `"data_dir": "../data"` 则写到仓库根的 `data/`（与播放端共用一份）。

```
data/
  2026-10-27/
    7734200/                        ← 房间号, 一个赛事日一个目录
      7734200_s0100.jsonl.gz        ← 整点切片
      7734200_s0200.jsonl.gz
      ...
      7734200.afp.jsonl             ← 音频指纹(自动校准的数据源)
      7734200.meta.json             ← 统计摘要
      manifest.json                 ← 数据契约(服务端优先读它)
  _test/                            ← 测试录制单独隔离
    2026-10-27T1022_7734200/
```

- **赛事日**：会话结束时刻所在日期。跨零点场次（23:33→次日 08:59）归到"打完那天"。
- **弹幕与指纹永远同目录**，自动校准才找得到。
- **重复运行不覆盖**：同日再跑会自动归档为 `_runN` 后缀，三件套共用序号。

### 各文件说明

| 文件 | 内容 |
|---|---|
| `{room}_s{HHMM}.jsonl.gz` | 整点切片，每行一条 JSON：`ts`(毫秒墙钟) / `un` / `t` / `ty`=dm\|sc |
| `{room}.afp.jsonl` | 音频指纹，帧长/频带与字节布局见 `SCHEMA.md` §4，整晚约 3.5MB，不落任何音频 |
| `{room}.meta.json` | 统计摘要：条数/重连/切片清单/结束原因等 |
| `manifest.json` | 契约文件：房间/起止时间/条数/文件清单/afp 参数 |

`ts` 优先取 B 站消息体的服务器时间（与本机墙钟差 >6 小时才回落本机时间），避免断线补发导致时间轴失真。

## config.json

| 字段 | 默认 | 说明 |
|---|---|---|
| `rooms` | `[]` | 直播间房间号，可多个。**必填**，留空启动即报错 |
| `earliest_start` | `"now"` | `now` / `HH:MM`（下一次出现）/ `+30m` |
| `latest_end` | `"09:00"` | 到点自动停止并收尾，`""` 表示不停 |
| `poll_interval_sec` | `60` | 未开播时的检查间隔，最小 5 |
| `audio_fp` | `true` | 是否采音频指纹。**强烈建议开**——关掉则该晚永久无法自动对齐 |
| `slice_minutes` | `60` | 切片周期，`0` = 不切片 |
| `data_dir` / `log_dir` | `data` / `logs` | 相对脚本目录 |

模板见 `config.example.json`。

## 音频指纹 sidecar

录弹幕的同时拉最低清晰度直播流，只解音频增量算指纹：

- CPU 增量 <3%，内存约 80MB，磁盘每晚 <10MB，**不落任何音频**。
- 断流自动退避重连（新段重锚墙钟）；失败只降级告警，不影响弹幕采集。
- ffmpeg 优先用系统 PATH 的（非 Windows 环境通常自带），否则用 imageio-ffmpeg 自带二进制。

## 健壮性

- **单实例锁** `logs/collector.lock`：重复启动（含 `--test` 与正式任务并发）会被拒绝，避免两个进程写同一数据片。
- **写盘失败**（磁盘满/句柄失效）打 ERROR 并计入 `meta.write_err_count`，连续失败 50 次明确告警"数据正在丢失"。
- **原子写**：meta/manifest 用临时文件替换，不会出现半截 JSON。
- **下播判定**：需连续 2 次（间隔 60 秒）确认，接口抖动不会提前结束。
- **切片时机**：收包循环和辅助循环都检查，断线重连等待期跨整点也能切。

## 测试

```bat
.venv\Scripts\python.exe collector.py --test 60
```

产物落在 `data/_test/{时间戳}_7734200/`，不混入正式数据。

## 注意事项

- **Windows 电源"睡眠"设为从不**（代码内置 SetThreadExecutionState 双保险，仅 Windows 生效）。
- 按 Ctrl+C 随时安全停止，已录数据正常收尾。`ended_by`：`latest_end`(到点) / `interrupt`(手动) / `test_done` / `error`。
- 整夜未开播则当天无正式记录，属正常（不写 meta，不产生垃圾文件）。
- 测试会话与正式会话用不同目录，`_test/` 下不会混进统计数据。
