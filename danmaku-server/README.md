# danmaku-server 伪直播播放端

把 danmaku-collector 采集的弹幕对齐到 B 站官方回放视频上，在本机把录播还原成一场"正在直播"的页面。总览见上级目录 `README.md`。

## 启动

双击 `伪直播.bat`，浏览器自动打开 <http://127.0.0.1:8789>。（换机器需重建 `.venv`：aiohttp + numpy + imageio-ffmpeg）

## 页面操作（日常三步）

1. 选**日期**（下拉显示「比赛日（数据 数据日）」）→ **弹幕会话**下拉每行显示
   `日期 时段（时长）· 弹幕条数 · 房间号`，按真实开始时间升序；默认自动选中**数据量最大的正式会话**（当晚正赛）→ 选**比赛场次** → 点「开始播放」。
2. 播放后每场点一次**「自动校准」**（校准面板的首选按钮）：服务端用直播音频指纹与回放音频互相关，1~60 秒解出 offset 并自动应用（置信度显示在校准卡片）。实测精度亚秒级。
3. 看比赛。弹幕密度/字号/数量档（全部/一半/较少/更少）按需调整，播放器控制条有弹幕快捷开关「弹」和全屏（全屏含弹幕层）。

辅助功能：
- **刷新赛程**：Riot 官方赛程自动发现当日场次 + B 站搜索官方回放 BV 回填（回放未上传时留空，中午后再点一次即可补齐）。
- **手动校准**（自动校准失败/需微调时的**兜底**，默认折叠）：在「当晚总览」的密度曲线上点事件标记（一血/大龙/水晶等自动识别）→ 画面事件发生瞬间点「对齐到此刻」，或 ±30/10/5 微调。所有校准即时持久化。
- **自定义回放源**：无场次数据时手填 BV+offset；选中场次时以场次为准（防旧值残留造成弹幕↔视频错位）。

> 密度图只有**一份**，放在「当晚总览」里（弹幕密度 + 每场每分P的轨道 + 事件标记 + 当前播放位置）。校准面板不再重复画密度曲线，只保留自动校准按钮与折叠的手动兜底入口。

## offset 语义

`offset_sec` = 弹幕墙钟锚点（anchor_ms，该会话数据首条时间）与回放 0 秒的差：
`直播墙钟 = anchor + offset + 视频内位置`。自动校准/手动校准/写回共用同一语义，前端无需理解细节。

## 数据目录

采集端把**每个会话**写在独立子目录里：`data/{数据日}/{数据日}_{开录HHMM}_{房间号}/`，内含该会话的切片、`afp` 与 `meta`。服务端读取层**同时兼容**新旧两种布局：

- 新：`data/{日}/{会话目录}/`（`layout: session`，`file` 参数即会话目录名）
- 旧：`data/{日}/{room}_sHHMM.jsonl.gz` 平铺（`layout: flat`）

`/api/days` 返回的每个文件条目带 `layout` 字段（`session`/`flat`）与 `start_ms`/`end_ms`（会话真实起止时间），前端据此决定显示与排序。

> `start_ms`/`end_ms` 是**扫描弹幕数据本身**取到的首尾 `ts`，不是读 `meta.record_start`。
> 原因：采集端的 meta 只覆盖最后一次收尾的片段（实测主会话 meta 记的是 08:45~09:00 的 281 条，
> 而实际数据是 23:33~08:59 的 20 万条），用 meta 当会话时间会严重错位。
> 另外会话目录里的文件名**不保证**等于目录名推导出的基础名（历史迁移的 `{room}_day0719`、
> 测试的 `test_HHMMSS_{room}`），所以服务端在会话目录内按"实际存在的文件"收集，而不是按名字前缀匹配。

历史平铺数据可用 `danmaku-collector/migrate_sessions.py` 迁移（默认预演）。

## 服务端 API（8789）

| 端点 | 说明 |
| --- | --- |
| GET /api/days | 数据日期列表（每个日期带 `match_date` 比赛日 / `data_date` 数据日；文件条目带 `layout`） |
| GET /api/danmaku?date&file | 弹幕全文（主文件+_runN 归档+_s 切片+活动 raw 合并按 ts 排序；支持边采边读；`file` 可为会话目录名或旧房间主名） |
| GET/POST /api/match | 对齐注册表读写（anchor 取数据首条，meta 兜底；写回原子替换+lists 同步带 bv 双保险） |
| GET /api/matchlist?date | 该日场次列表（按数据首条时间自动路由到正确比赛日的赛程） |
| GET /api/discover?date | Riot 赛程发现 + B 站 BV 搜索回填（内存缓存/退避/只回填空位） |
| POST /api/autocalign | 音频指纹自动对齐（读 afp→回放指纹(缓存)→长段滑窗互相关→写回；conf<2 拒绝） |
| GET /api/playurl?bv&page | B 站 html5 mp4 直链解析（多段返回 urls+seg_lengths） |
| GET /api/stream?url | CDN 反代（带 Referer/UA，Range 透传，SSRF 防护） |

## 文件

- `audiofp.py`：指纹算法（0.4s 窗 33 对数频带能量 + L2 归一化）与 afp 解析、FFT 互相关对齐（抛物线亚帧插值）。
- `matches.json`：`align`（`会话日|文件` → bv/offset_sec/auto）+ `lists`（`比赛日` → 场次数组）。全部原子写入。
- `web/`：无框架原生 JS。弹幕 canvas 引擎（预渲染 sprite、轨道分配、多段虚拟时间轴）、当晚总览（密度图+轨道+事件标注）、场次点选。

## 已知边界

- 取流走 B 站 html5 平台，通常最高 720P；直链偶发 403 自动走反代兜底。
- 官方重导音轨的场次音频对齐必失败（自动拒绝并提示），用总览密度图 + 事件标记手动校准兜底。
- 防剧透：页面不显示比分；时长进度条可见（自由拖动，锁定伪直播模式已移除）。事件标记会透露比赛进程，可用总览的「显示事件关键词」开关整体隐藏。
