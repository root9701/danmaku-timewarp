# LOL 延时伪直播（Danmaku Replayer）

把 B 站赛事直播间的弹幕整夜录下来，第二天对齐到官方回放视频上，在本地网页里把"录播"还原成一场"正在直播"——弹幕跟着画面飞，像回到比赛当晚。

为英雄联盟全球总决赛（Worlds）瑞士轮/淘汰赛设计：比赛在北京时间凌晨 1~8 点，睡醒后打开网页即可"伪直播"回看。

```
┌─────────── 夜间 ───────────┐      ┌─────────── 次日 ───────────┐
│  danmaku-collector         │      │  danmaku-server            │
│  定时开录 → 录弹幕 → 切片   │ ──►  │  选场次 → 自动校准 → 播放   │
│  同时算音频指纹            │      │  弹幕跟画面飞               │
│  到点自动收尾              │      │  视频流直连B站CDN, 不落地    │
└────────────────────────────┘      └────────────────────────────┘
```

## 快速开始

**每晚睡前**：双击 `danmaku-collector/启动采集.bat`，窗口可最小化，别关。

**次日早上**：双击 `danmaku-server/启动回放台.bat`（想在 iPad 上看用 `启动回放台_局域网.bat`）
→ 浏览器开 http://127.0.0.1:8789 → 选日期和场次 → 点「开始播放」→ 点「自动校准」。

**官方回放通常中午前后才上传完整**，早上若有场次缺 BV，中午点一次「刷新赛程」即可补齐。

## 配置（换赛事 / 换房间 / 换时区）

两端各有自己的 `config.json`，**都不进版本库**，改完重启生效。
删掉也能用内置默认值启动。均有 `config.example.json` 模板可抄。

### 采集端 `danmaku-collector/config.json`

| 字段 | 默认 | 说明 |
|---|---|---|
| `rooms` | `[]` | 要采集的直播间房间号，可多个。**必填**，留空启动即报错 |
| `earliest_start` | `"now"` | `now` / `HH:MM`（下一次出现）/ `+30m` |
| `latest_end` | `"09:00"` | 自动停止时刻，空串表示不停 |
| `poll_interval_sec` | `60` | 轮询间隔，最小 5 |
| `data_dir` / `log_dir` | `data` / `logs` | 相对脚本目录 |
| `audio_fp` | `true` | 是否采音频指纹。**强烈建议开**——直播流过后就没了，事后无法补 |
| `slice_minutes` | `60` | 弹幕切片间隔，`0` = 整晚一个文件 |

### 播放端 `danmaku-server/config.json`

| 字段 | 默认 | 说明 |
|---|---|---|
| `port` | `8789` | 网页端口 |
| `host` | `127.0.0.1` | 监听地址。`0.0.0.0` = 局域网可访问（无鉴权，只在可信网络用）。注意 `启动回放台_局域网.bat` 会用环境变量临时覆盖为 `0.0.0.0`，不依赖此字段 |
| `discover.enabled` | `true` | 是否自动发现赛程 |
| `discover.league_id` | Worlds | 抓哪个赛事，见下表 |
| `discover.timezone` | `Asia/Shanghai` | IANA 时区名。**Windows 需先 `pip install tzdata`** |
| `discover.window_start` / `window_end` | `01:00` / `09:00` | 赛程过滤窗口；结束早于开始表示跨零点 |
| `bili.official_mid` | `50329118` | B站官方回放账号 |
| `align.min_confidence` | `2.0` | 对齐置信度下限 |

常用 `league_id`：

| 赛事 | ID |
|---|---|
| Worlds | `98767975604431411` |
| LPL | `98767991299243165` |
| LCK | `98767991310872058` |
| LEC | `98767991302996019` |

**换赛区示例**——录 LPL（北京时间晚上开赛）：

```json
{
  "discover": {
    "league_id": "98767991299243165",
    "window_start": "16:00",
    "window_end": "23:00"
  }
}
```
采集端相应改 `earliest_start: "16:00"`、`latest_end: "23:30"`。

**换直播间**：只改采集端 `rooms`，播放端无需改。

环境变量（优先级高于 config.json）：`DANMAKU_CONFIG`（配置路径）、`DANMAKU_DATA`（数据目录）、`DANMAKU_HOST`（监听地址）、`RIOT_API_KEY`、`AFP_CACHE`。

## 核心机制

### 1. 采集

- **状态机**：等到定时 → 轮询开播 → 录制 → 下播等待重开 → 到点收尾。多场比赛共用一次运行。
- **弹幕协议**：B 站 WS，APP 签名 token + buvid3 预热（规避风控）；断线指数退避重连。
- **整点切片**：`{room}_s{HHMM}.jsonl`，每片完成即 gzip。
- **防覆盖**：同日重复运行自动归档为 `_runN` 后缀，弹幕/指纹/meta 共用序号。
- **收尾**：gzip + 写 `meta.json` + `manifest.json`（契约见 SCHEMA.md）。

### 2. 音频指纹自动校准

**原理**：直播弹幕墙钟与回放视频时间只差一个固定 offset。夜里录弹幕时顺便拉最低清晰度直播流，只解音频算指纹（33 频带，0.2s/帧，整晚约 7MB，CPU<3%，不落音频）；白天与官方回放音频做互相关，解出 offset。

**逐分P 独立对齐**：官方回放按"第一局/第二局/赛前评论/赛后采访"拆成多个分P，每个分P 是独立的直播切片，各有自己的 offset。分P 个数由程序从 B 站接口读，不写死——Bo1 是 2P（对局+评论），Bo3 是 2~3P，Bo5 更多，都按实际返回处理。

**实现**：把每个分P 的指纹切成 8 段（每段约 3 分钟）分别定位，按 30 秒容差聚类投票。
短片段比整段对齐更可靠——整段里混进一段直播没播的内容就会把得分拉平。

**判定看投票一致性，不看单段置信度**：单段 conf 反映"这 3 分钟音频本身有多独特"，BP/解说段天然不独特（低到 1.1）但不代表位置错。实测 T1 vs CFO 第一局 8 段全部指向同一位置（离散 0.0 秒），只有 1 段 conf=8.28——若先按 conf 过滤就只剩 1 票，正常比赛会被判失败。

采信条件（其一即可）：票数 ≥ 1/3、强票（conf≥6）≥ 2 张、1 张强票（conf≥7）且总票数 ≥ 2、全票一致且最强票 ≥ `min_confidence`。

**赛程窗口**：直播间早上会把前几场重播一遍，音频与官方回放完全一致，投票也会一致命中。因此按官方赛程开始时间算允许区间（提前 90 分钟 ~ 整场结束 +30 分钟），窗口外的一律拒绝并提示"疑似重播"。

多个自洽位置时**取最早的那个**（那是当时正在直播的那次）。

### 2b. 播放时的分段映射

播放器把各分P 首尾相接拼成一条虚拟时间轴，但直播侧两局之间有局间休息、官方回放剪掉了。
所以每个分P 用**自己的 offset** 映射弹幕：

```
分P k 占虚拟轴 [S_k, S_k+Dur_k)
虚拟位置 v 的墙钟 = anchor + offset_k*1000 + (v - S_k)*1000
```

用单个标量 offset 等价于假设"各分P 无缝相连"，从第二局起就会错位——实测 AL vs TLAW
第二局偏 −213.9 秒、第三局 −207.8 秒。局间休息里的弹幕直接丢弃，不压缩到相邻分P。

### 3. 赛事日归属

**赛事日 = 会话结束时刻所在日期**。

跨零点的场次（23:33 开录、次日 08:59 结束）归到"打完那天"，符合直觉。
目录名一旦确定即锁定，避免录制中与收尾时算出不同日期。

### 4. 赛程与 BV 自动发现

Riot esports API 取当日比赛块 → 生成场次草稿 → B站搜索官方账号的单场回放标题匹配两队名 → 回填 BV。
回放未上传时留空，之后一键刷新补齐。写回遵循"只回填空位，绝不覆盖已有 BV/offset"。

### 5. 手动微调（兜底）

自动校准不准时，展开「手动微调」用 ±30/10/5 秒逐档校正，即时生效并持久化。

## 数据格式

### 弹幕文件 `{room}_s{HHMM}.jsonl(.gz)`，每行一个 JSON

```json
{"ts": 1792942382304, "un": "用户名", "t": "弹幕文本", "ty": "dm", "price": 0}
```
`ts` 为毫秒墙钟（对齐的锚点），`ty`: `dm`|`sc`。测试录制前缀 `test_`。

### 音频指纹 `{room}.afp.jsonl(.gz)`，四种行

```
{"ty":"hdr","v":1,"sr":16000,"hop":0.2,"win":0.4,"bands":33}
{"ty":"conn","c":0,"t0_ms":1792942382000}          // 拉流连接段
{"ty":"fp","c":0,"ts":...,"n":300,"fp":"<base64>"} // 60s 一批
{"ty":"end","c":0,"reason":"reconnect"}
```

### matches.json（对齐注册表 + 场次列表）

```json
{
  "align": { "2026-10-27|7734200|BV1xx": {"bv":"...","offset_sec":5272.5,"pages":{...}} },
  "lists": { "2026-10-27": [ {"title":"T1 vs CFO","bv":"...","offset_sec":5272.5,
                             "start_ms":1793034000000} ] }
}
```
align 键 = `赛事日|文件名`, 多场次时追加 `|BV`；lists 键 = 赛事日。写入原子替换（tmp+rename）。
`start_ms` 是官方赛程开始时间（对齐时的时间窗依据）。

## 日常运维

两端各有自己的开关脚本，都在各自目录里，互不影响。

| 采集端 `danmaku-collector/` | 作用 |
|---|---|
| `启动采集.bat` | 前台运行，窗口里能看实时进度。**关窗 = 停止采集** |
| `启动控制台.bat` | 网页控制台(8787)，可改配置、看进度、手动启停 |

| 播放端 `danmaku-server/` | 作用 |
|---|---|
| `启动回放台.bat` | 前台运行，仅本机可访问。**关窗 = 停止服务** |
| `启动回放台_局域网.bat` | 前台运行，手机/iPad 可访问，窗口里显示二维码 |

两个启动脚本都是前台运行 —— 关窗即停，不留后台进程。

**局域网访问需要防火墙放行。** 若手机连不上，用管理员 PowerShell 执行一次：

```powershell
New-NetFirewallRule -DisplayName "弹幕回放台" -Direction Inbound -Protocol TCP -LocalPort 8789 -Action Allow -Profile Private
```

并检查有无针对 python.exe 的入站拦截规则（有则删除）：

```powershell
Get-NetFirewallRule -Direction Inbound -Action Block | Where-Object { $_.DisplayName -eq "python.exe" }
```

## 手机备份节点（可选）

PC 与手机同时采同一房间，数据独立落盘，任一节点故障不丢当晚弹幕。

- 环境：Termux + python/numpy/ffmpeg，代码经 `adb reverse` 隧道拉取。
- 保活：`termux-wake-lock` + Doze 白名单；vivo 的 ABE 后台管理需手工豁免。
- 管理：`phone_ctl.py status|start|stop|log|pull|test`。
- 已知限制：Termux 的 Python 与 numpy ABI 兼容问题可能令指纹在手机上降级（弹幕不受影响）。

## 已知边界

| 情况 | 表现 |
|---|---|
| 直播只播了部分内容 | 该分P 只有部分片段能对齐，其余回放内容播不了 |
| 某分P 内容在直播开播前（如赛前评论） | 该分P 报"找不到自洽位置"，其它分P 正常 |
| 早上重播了前几场 | 按赛程窗口拒绝并提示"疑似重播"，不会错位采纳 |
| 官方回放重导音轨 | 自动校准拒绝，需手动微调 |
| 采集时关了 `audio_fp` | 该晚永远无法自动对齐（指纹无法事后补） |
| 同一天多次运行 | 自动归档为 `_runN`，数据不丢但会分成多个会话 |
